# Bounded context exploration and review presentation

The existing immutable collection and isolated Codex execution remain in place. Changed base/head files and trusted default-branch instructions are still required evidence. Direct JS/TS dependencies, simple Python relative imports and Rust sibling modules are resolved without executing project code. Python/Go/Java test naming heuristics supplement the existing nearby tests/manifests.

The collector writes `/workspace/file-index.json`: at most 12 nonrecursive directory walks and 5,000 regular-file paths. A partial supplementary index does not invalidate a small PR. It does not imply exhaustive semantic coverage. No full recursive tree or unrelated blob download is required.

A separate trusted host Unix socket at `/run/proxy/context.sock` accepts only POST `/file` JSON with `snapshot: base|head` and a relative `path`. Successful retrieval materializes a verified file under the existing read-only reviewer mount. Paths, immutable commit/tree/blob identity, object modes, UTF-8, size and Git blob SHA are validated by the same collector. It cannot request another repository/ref, fetch URLs, follow symlinks or execute commands. There are at most 24 lookups, sharing the 768-call/16-MB-source/512-KB-file limits and SHA cache. Missing explicitly requested evidence makes the result incomplete and fails the review job. Optional omissions that were never needed do not.

The GitHub read token remains on the trusted host through bounded exploration, rather than being revoked before inference. It is never mounted into the reviewer or credential proxy. On completion/failure, the host aborts/drains outstanding lookups, closes the context service, revokes the token and removes temporary source. Token cleanup failure fails the review job; it does not authorize approval. The separate publisher still uses the job conclusion and exact commit to decide whether a safe COMMENT is appropriate.

The concise permanent prompt asks Codex to understand changed behavior and trace important unchanged callers, data flows, tests, security and compatibility. Trusted project guidance cannot override safety/output rules; task-specific comment context only steers attention. Untrusted repository instructions cannot change credentials, authorize publication/merge or grant tools. Existing client-side approval requests stay denied and Docker stays network=none, nonroot, read-only, capability-free and credential-free.

Human-readable summaries distinguish clean completion, advisory findings, changes requested and incomplete evidence. They omit routine “merge not requested”/mechanical decision noise. Actual native APPROVE/COMMENT/REQUEST_CHANGES decisions, confidence policy, DLP, changed-line validation, publication fingerprints and merge restrictions remain independent of that wording.

Validation: immutable lookup/path/type/budget tests, small PR in a 1,200-file repository, native Codex/Docker reads of exact diff/base/head/trusted instructions/unchanged caller/hostile-text hashes, denied writes/network/credentials and full severity/confidence/completeness summary checks. Scripted Responses exercise real tools and sandbox behavior, not real AI recognition or prompt-quality improvement. Live old/revised-prompt comparison on identical clean/buggy/security/cross-file fixtures requires separate owner authorization; no paid or ChatGPT inference is part of CI.

Runner changes require coordinated Worker/caller pins to the actual merged source revision. Never guess a merge SHA or use a branch/tag. Close the production merge gate for the coordinated upgrade, then restore it only after verifying matching Worker/caller pins.

## Large PRs and binary coverage

The exact base-to-head aggregate diff covers all PR commits together. The collector does not promise per-intermediate-commit analysis. Up to 200 changed files, 6 MB of serialized diff, 16 MB of materialized text, 512 KB per text file, 768 GitHub calls and 120 seconds of initial collection are supported. Individual API calls time out after 15 seconds. Commit/tree/blob caches are local to this tenant and review; identical blobs are fetched once. Changed files and trusted AGENTS.md precede optional context. On-demand requests share the remaining byte/call budget. Precise failure codes and non-approving summaries explain exhausted budgets.

Missing patches are never assumed binary merely from extensions. Supported PNGs require exact immutable tree paths, regular non-executable blobs, verified Git blob SHA/size and PNG signature/chunk framing through IEND without trailing payload. Both base/head versions are verified as applicable to addition, modification, deletion and rename. Binary reads are bounded to 2 MB/file and 8 MB total unique content. The trusted collector never decompresses or renders images, and binary bytes are not installed as UTF-8 source. It materializes verified base/head PNGs separately under `/workspace/media`. The engine supplies official App Server `localImage` inputs with immutable path/side labels, deduplicated by blob SHA (at most 16 unique images). The selected model must advertise image input. The credential proxy requires the expected number of actual base64 image inputs on each inference request and denies remote image URLs, uploads, audio/video and generic file inputs. Missing or rejected images cannot produce an approval. Image text is untrusted data, never instructions. Unknown formats (including audio, executables, archives and extension spoofing), missing/truncated text and unverifiable essential files remain fail-closed.

The publisher independently verifies PNG evidence within 32 additional Git calls. A complete text-and-image analysis uses the ordinary confidence/verdict policy; unavailable visual evidence remains incomplete and cannot approve or merge. Image findings use `line: null` and appear in the overall review, since GitHub cannot anchor inline comments to image pixels. Text findings still require actual changed lines.

The pinned Codex 0.169.0 App Server supports `localImage`; its current adapter has no general local-file input. [Official SIWC limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) allow model-supported images/files on Responses, but exclude audio/video input, transcription and Files API uploads. This implementation supports verified PNG images, not every binary format. It does not execute, unpack, transcribe or silently skip EXE/archive/audio/PDF files. Those changes require a supported explicit inspection path before approval. No private ChatGPT endpoints or paid fallback are used.

The Docker acceptance uses the actual pinned Codex binary to prove PNG conversion, transport, tool inspection and isolation against scripted Responses. It is not proof of real-model visual understanding; no new real-provider inference is part of this hotfix validation.


Final completion is checked again by the trusted host after the isolated engine returns and the context service is closed/drained. A missing requested file remains essential missing evidence even if the model returns complete findings or has inspected every attached PNG. The host preserves validated findings in the non-approving submission, fails the review job and logs only completion booleans/result enum plus an approved context failure code. On-demand failures enter required coverage diagnostics rather than being labeled supplementary omissions. Paths, model text and credentials are not diagnostic fields. Neither a later successful lookup nor a complete model result clears a previous essential-evidence failure.
